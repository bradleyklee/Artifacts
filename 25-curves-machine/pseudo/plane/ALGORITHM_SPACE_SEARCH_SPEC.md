# PlaneCurveODE algorithm-space search specification

## Project objective

The immediate examples are polynomial Hamiltonians, but the higher-level
object being searched is an algorithm.

The project alternates between:

1. searching a bounded reduction space for one Hamiltonian;
2. extracting the successful or failed mechanism into language-neutral
   pseudocode;
3. comparing that pseudocode with the existing library;
4. mutating or combining candidate algorithms;
5. rerunning the expanded portfolio.

Thus the outer loop searches algorithm space, while each candidate algorithm
searches reduction space.

```text
examples -> reduction traces -> pseudocode mutations
         -> algorithm comparison -> improved reduction search
```

Use dissertation notation throughout:

```text
H       Hamiltonian
alpha   energy parameter, usually alpha = 2H
T       period
S       action
A       annihilator
Xi      telescoping certificate
```

Do not use `K` for the Hamiltonian or `L` for the annihilator.

## Reduction-space coordinates

A reduction algorithm is specified by choices in the following slots:

```text
input normalization
coordinate system
algebraic extension / quotient algebra
basis and monomial order
period or action differential
parameter derivation
base-variable derivation
finite pole divisors
infinity treatment
pole-lowering rule
canonical remainder representation
dependence / kernel search
annihilator normalization
certificate reconstruction
right-factor and minimality search
coefficient-relation analysis
integer period normalization
verification and serialization
```

Two algorithms that differ in any slot remain separate candidates until an
exact bridge proves them equivalent.

## Algorithm-space operations

Candidate algorithms may be generated by:

```text
specialize       restrict an existing algorithm to a smaller family
generalize       enlarge its coefficient field, basis, or pole model
change-chart     replace the base variable or algebraic generator
change-basis     seek a smaller or more integral quotient basis
compose          join a recognizer, reducer, factorer, and verifier
hybridize        use series/modular evidence to guide exact reduction
transpose        exchange shift reduction and parameter differentiation
compress         use symmetry invariants or a common angular frequency
decompress       return to a full affine or action-fiber algebra
factor           certify a smaller right factor of a known annihilator
mutate-bound     change derivative order, pole order, or numerator box
reuse-obstruction
                 construct a controlled example exercising a prior failure
```

## Evidence states

Every pseudocode candidate has one status:

```text
idea
specified
implemented
exact_on_examples
certificate_verified
portfolio_regression
limited_by_counterexample
superseded
```

A modular rank signal, guessed recurrence, or numerical agreement cannot
advance a candidate to `certificate_verified`.

## Search policy

The portfolio deliberately mixes known and unknown cases.

```text
known case
    -> verify old mechanism exactly
    -> extract reusable pseudocode
transfer case
    -> expose the first missing assumption
    -> mutate the smallest algorithmic component
hard case
    -> preserve obstruction and last valid exact object
controlled return
    -> test the mutation on a case with known output
```

Do not attempt to complete a universal reducer before running this cycle.

## Progress-report contract

Each research checkpoint must report:

```text
TARGET:
ALGORITHM CANDIDATE:
PSEUDOCODE CHANGE:
EXACT DATA:
RELATION SIGNATURE:
FAILURE OR OBSTRUCTION:
SAVED ARTIFACT:
NEXT ALGORITHM MUTATION:
```

Claims not backed by a saved replay artifact are labeled `provisional`.
